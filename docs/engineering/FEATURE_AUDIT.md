## Product-owner direction — freelance and remote-work platform (2026-10-28)

Kaira Africa must serve small-business operators and remote workers/freelancers who manage client deliverables, workload, assignments, deadlines and progress. The former “Visual Assistant” entry is being positioned as “Freelancer & Remote Work” so the purpose is clear: help users turn client briefs into proposals, milestones, task lists, estimates and progress updates. AI-generated drafts must remain reviewable; no AI action should create or modify records without explicit confirmation. The assistant must not claim to visually inspect screens or uploaded files unless those capabilities are implemented and tested.

Agreed connected scope to preserve across phases: (1) in-app task notifications, web push/PWA and email fallback, configurable due-date reminders and overdue escalation; (2) business-scoped team chat and announcements; (3) transparent staff presence (online/away/offline) and task-linked start/stop time entries, with employee visibility and manager reports; (4) subscription plans Starter/Pro/Max with verified payment state, expiry/grace rules, usage entitlements and automatic fallback to Kaira Africa branding after custom-brand entitlement expires; (5) freelancer/client workspace with proposals, deliverables, project/task tracking and progress updates. Do not implement covert keystroke/screen monitoring. Do not treat this scope register as evidence that the features are implemented.

## CRM photo reliability follow-up (2026-10-29)

The open branch `fix/crm-photo-signed-preview-reliability` addresses a second photo-success reporting risk found during the route review: the CRM photo endpoint could persist the new private object path and then return a null avatar if signing failed during serialization. The branch now requires a signed preview before replacing the database path, cleans up the newly uploaded object if signing fails, preserves the existing customer photo on that failure, returns the already-verified URL for the successful upload response, and adds helper tests for signed URL parsing and exact business/customer path ownership. This is code-level protection only; it does not prove authenticated CRM upload/replace/reload or tenant-isolation behavior.


## Continuation record — appearance and inventory/daily-sales consistency (2026-10-29)

- Source inspection confirmed the Appearance tab was a non-functional selector: its state changed only the selected card, no root dark class was applied, and the page explicitly said theme switching was not wired up. Branch fix/appearance-and-inventory-sales-consistency now applies light/dark/system themes, persists the preference as kaira-theme in browser storage, and listens for operating-system theme changes in system mode. This remains pending CI and deployment verification.
- Source inspection confirmed the Daily Sales & Expense Book already reads the inventory product list and the API can atomically record a linked sale, decrement stock, write a stock movement, and insert the ledger entry. However, the ledger API currently accepts GMD only while inventory supports GMD/NGN/USD; the previous selector could offer non-GMD products and store their amount under GMD. The branch restricts linked sale choices to GMD-priced products and adds a backend currency mismatch guard so such sales cannot silently be mislabeled. Proper NGN/USD ledger filters and per-currency summaries remain not implemented and must be completed before enabling those products in daily sales.
- Inventory plus/minus buttons are stock adjustments, not a complete point-of-sale flow. Their copy now distinguishes stock removal from a recorded sale; users must record a real sale in Daily Sales & Expense Book to capture revenue and update stock together.
- No production business records or Storage objects were changed. Required checks: frontend/backend typecheck, frontend build, API tests, fresh DB migration validation, Docker build, Render deploy verification, and authenticated/isolated tests for theme persistence/system switching, linked GMD sale + stock update, insufficient stock, and currency mismatch.
